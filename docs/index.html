Your API workspace behaves like the rest of your codebase.

Most API clients lock your work inside a proprietary cloud account. Here, a changed header is a one-line diff you can review in a pull request — not an opaque blob you hope synced correctly.

Version-controlled

Commit it, branch it, and review API changes in the same PR as the feature they test.

Portable

It's just files. Back your workspace up by pushing it to git — there's nothing else to export.

Private by default

Nothing leaves your machine. No account, no cloud sync, no telemetry. Secrets stay out of git.

Diffable

Human-readable YAML means every edit shows up as a clean, reviewable line — like the one on the right.

A full API client — it just happens to save as text.

Sync to any folder

Link a collection or environment to a folder inside a git repo, and its YAML is kept in sync right there.

Environments

Switch dev / staging / prod with {{variable}} substitution. A per-environment color keeps prod distinct.

Auth, done for you

Basic, Bearer, API Key, and full OAuth 2.0 — tokens are fetched, cached, and their expiry shown.

Scripts & tests

Pre-request and post-response JavaScript with assertions via ac.test() and dynamic {{$guid}} variables.

Import what you have

Bring in v2.1 collection exports or OpenAPI 3.x / Swagger 2.0 specs — converted to native YAML.

Mock server

Spin up a mock HTTP server from any collection and serve its defined responses on localhost.

Live reload

Edit a YAML file in your own editor and the UI updates instantly over Server-Sent Events.

cURL, instantly

Turn any request into a ready-to-run cURL command to paste into a terminal or a ticket.

No database

There's nothing to migrate or corrupt. The filesystem is the store, and text is the format.
